# Expected versus predicted

The [CSV table](golden_dataset_with_predictions.csv) follows the comparison format
in the supplied screenshot. For a routing agent, use `expected_intent` and
`predicted_intent`. For Fundamentals, use `expected_value` and `predicted_value`.

Read the [dataset balance and coverage analysis](dataset_analysis.md) alongside
these outcomes. It describes which kinds of examples we have, independently of
whether the agent passed them.

The [pass/fail category analysis](result_analysis.md) reports accuracy, precision,
recall, F1, units and evidence scores by scenario, financial category and field.
The CSV now includes `scenario`, `metric_category`, `result_category` and
`suggested_correction`. These are analysis annotations; the human-comments
column remains separate and unchanged.

Each row represents one requested field for one company, date and accounting
basis. The visible comparison is:

`field | expected_value | predicted_value | expected_unit | predicted_unit | result | reason | human_comments`

`human_comments` is a blank, editable column beside `reason`. Use it for the human
reviewer's diagnosis and proposed correction for a failed row. The existing
`reason` contains the saved run's outcome and source-check status. Human comments have not been
invented or filled on the reviewer's behalf.

For example, a reviewer could write: “Cause: the reported decimal ratio was
rejected. Correction: convert 0.21 to 21% before validating ROE, preserving its source.”
This example is guidance, not a recorded human judgment. The agent now applies
this conversion, as documented in the [fix verification](fix_report.md).

The remaining columns identify the case, agent, company, date, basis, source,
real/synthetic data and review status.

`NOT_RETURNED` is a display marker for a field absent from a completed agent run.
It is not text generated by the agent and does not replace a missing value in
the raw run or grader. These ten rows have specific failure reasons. A predicted
`UNAVAILABLE` would require an explicit unavailable response from the agent.
An expected `UNAVAILABLE` means the supplied evidence does not support that
field; it is not a zero value. No rows remain `NOT_RUN`.

Numbers still use the agreed ±5% relative tolerance. Units, company, period and
basis must match, and citations must support the claim. A simple display of
PASS/FAIL does not change those [grading rules](metrics.md). Future results can
also use `PENDING_REVIEW` for unresolved evidence support and `ERROR` for execution
failures, keeping both outside pass/fail totals until resolved.

This CSV is an editable snapshot of saved results. Editing it does not rerun the
agent or automatically change the answer key. Keep this combined table away from
agent inputs because it includes expected answers. This view reads the saved
all-cases run; exporting the table does not call the model again. Human comments
and all expected-value cells are preserved.
